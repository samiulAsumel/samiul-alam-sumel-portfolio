A Real Example of the Approach

Illustrative summary — no real records or figures are shown.

  1. Operational problem

    The port's billing system creates permanent entries, so customs & freight-forwarding (C&F) agents could not check wharf rent (port facility usage charges) before committing. The result was billing disputes, longer cargo dwell time and repeat trips to the counter.

  2. Operational understanding

    • Cargo and vehicle workflow
    • Billing scenarios
    • Free time
    • Wharf-rent slabs
    • VAT and levy
    • Inside / outside storage
    • Rate changes mid-storage
    • Records and print needs

  3. System approach

    The workflow became structured forms, business rules and calculations, saved bills with live search, a dashboard and print-ready A4 invoices, because agents still work from paper.

  4. Result

    A practical web-based operational system designed around the actual workflow, used at the billing counter to verify charges before final submission.

  1. Operational need

    Vehicle positions across warehouse, shed and yard lived in one person's spreadsheet. When they were away, the team lost visibility.

  2. Vehicle and delivery information

    Daily receipts and deliveries are recorded per location, and the app works offline because terminal connectivity is not guaranteed.

  3. Tracking and records

    Every save is stored as a version-controlled commit, so there is a full history and any earlier version can be restored.

  4. Balance calculations

    Each location's closing balance carries forward as the next day's opening balance, adjusted by receipts, deliveries and transfers, with a holiday calendar for working days.

  5. Search and reporting

    Charts, report sections, Excel export and a keyboard quick-navigation palette.

  6. Result

    A working web system the whole department can check and update, replacing a single-person file.
