Transport Operations / Vehicle Tracking / Reporting

Vehicle Tracking / CarView

A shared, offline-capable system for tracking daily vehicle receipts, deliveries and balances across port storage locations, with reporting and a full change history.

Operational system

01Business problem

Vehicle positions across warehouse, shed and yard were recorded in one person’s personal spreadsheet, invisible to everyone else. When that person was unavailable, the whole team lost visibility of where vehicles were held.

The need was to keep movement information organised, shared and traceable, at terminal locations where connectivity is not guaranteed and there was no budget for a hosted database.

02Existing workflow

Tracking here means quantity and movement records per location per day. It is not GPS tracking.

  1. Vehicle movementsVehicles received into, and delivered out of, a storage location.
  2. Operational recordOne entry per location per day.
  3. Delivery / movement informationReceipts, deliveries and transfers between locations.
  4. BalanceEach day closes with the prior balance adjusted by movements.
  5. Search and trackingMonth navigation and a keyboard quick-navigation palette.
  6. ReportingCharts, report sections and Excel export.
  1. Personal spreadsheetOne person’s file.
  2. Daily recordsReceipts and deliveries per location.
  3. Business rulesRunning balance, holidays, transfers.
  4. Web systemShared, offline-capable.
  5. Structured data + reportsVersion history, charts, exports.

The software is built around the process, not the other way around. Designed to reduce repetitive spreadsheet-based work.

03My approach

I kept the running-balance logic staff already used on paper, where a location’s day closes with the previous closing balance adjusted by that day’s receipts and deliveries, and made it automatic. Then I added what a personal file could not give: shared access, offline entry and a history of every change.

  1. Real operational workflowDaily receipts and deliveries per location.
  2. Business rulesCarry-forward balance, working days, transfers.
  3. Structured dataOne dated record per location per day.
  4. Calculation logicBalances recomputed from the records.
  5. Web interfaceDaily entry, charts, reports, transfers.
  6. ReportsReport sections and Excel export.

04System design

With no database budget, the data store is a private GitHub repository: every save becomes a version-controlled commit, which gives a full audit history without a database to host.

  1. UserTraffic staff, on desktop or phone.
  2. Installable web appOffline-first; entry works without a connection.
  3. Business rules and calculationBalances and reports computed from the records.
  4. Cloudflare WorkerAuthenticated writes; the GitHub token never reaches the browser.
  5. Private GitHub data repositoryEvery save is a commit, with in-app version history and restore.

05Key features

  • Daily entryAcross eight storage locations: warehouses, yards and sheds.
  • Automatic balancesOpening and closing balances carry forward day to day.
  • Rotation numbersInline-editable per row and included in exports.
  • Car transfersBetween locations, with history; balances cascade forward.
  • Holiday calendarWeekends and public holidays marked for working-day logic.
  • Analytics chartsSeven charts plus summary cards.
  • ReportsThirteen report sections with period filters.
  • Excel exportFor anyone who needs the data outside the app.
  • Version historyAny earlier version can be restored.
  • Quick navigationCtrl+K palette for tabs, months, locations and reports.
  • Offline-first PWAInstallable, with a card layout on phones.
